## 3. Localization

**PROVEN.** The old DLL queued a line only when it contained the English substring " that". A non-English install got no reaction card. That prefilter is gone. Every non-empty line is copied (200 bytes, on a UTF-8 boundary) and classified on the task thread.

GMST reads use `GameSettingCollection::GetSingleton` (id 938225) and `GetSetting` (id 49324). Both ids are non-zero in libxse `9d090c4`. `REL::ID::id()` returns the number and does not look up an address. A zero id is not called. Before either call, the plugin reads `versionlib-<game version>.bin` beside the DLL and accepts the id only when that file is a v5 table and the id's slot is non-zero. A missing file, a non-v5 file, a slot of 0, or an id past the table skips the read and logs `hud gmst: address id <id> does not resolve, English fallback`. That lookup is not attempted, so a missing id cannot end the process. `IDDB::offset` would, and SEH cannot catch it. The read is read-only, after data load, on the task thread, inside an SEH wrapper. The string is copied immediately, at most 160 bytes, on a UTF-8 boundary. An empty value or a value that starts with `<ID=` keeps the English phrase. Each key is logged once as `hud gmst <key>: text|empty|stub "..."`.

The four affinity GMSTs, plus busy, calmed, creature calmed, pickpocket caught, and pickpocket fail, are the runtime phrases. English defaults:

- `liked that.` / `loved that.` / `disliked that.` / `hated that.`
- `This individual is busy.`
- `is calmed and cannot respond.`
- `The creature is calmed and cannot respond.`
- `has already caught you.` (the table's leading space is trimmed)
- `You've been caught pickpocketing.`

**NOT FOUND.** Whether those GMSTs are resolved text at runtime or `<ID=…>` stubs. The log line is the check. Address ids 938225, 49324, and 47401 were not checked against a 1.16.244 Address Library file in this session. The file is Nexus mod 3256 (v22, "All in one", 1.16.244.0). No public copy was available here. The plugin now skips any of those ids that do not resolve, instead of calling it.

**INFERRED.** The name is the prefix in front of the phrase. That matches the English affinity lines. Word order in other languages is unverified. A line that does not end with the phrase fails closed and the game's line stays.

`disliked that.` ends with `liked that.`, so dislikes and hates are tested first. If the dislikes phrase has been replaced and the likes phrase is still English, a line that still ends with `disliked that.` is not claimed as a like.

Present-tense English (`likes that.` and the other three) is used only while the likes GMST is still the English phrase.

## 5. Cards

**PROVEN in source.** The movie does not parse a live line. The DLL calls `hzcCardPush(kind, sub, name, value, raw)`. `hzcRxPush` remains for the old backup and the self-test. If the movie has no `hzcCardPush`, the DLL logs `Horizon messages movie is not active` once and does not hide a line.

The game fades `Internal_mc` (a color transform: frame 1 at 0, fade-in through 27 and up, fade-out 205, 154, 102, 51, 0). The movie never writes `Internal_mc.alpha`. After the Horizon card is visible and has a width, it sets `Internal_mc.Text_tf.visible` and `Internal_mc.Background_mc.visible` to false. Those children are not tweened. The card's alpha is `it.alpha * Internal_mc.alpha * Messages_mc.alpha`, so it follows that fade. Ending the card, dropping it when the list passes 8, turning cards off, or failing to sit restores those two children only when that entry set `covered`. An unknown line is not written. Nothing is deleted.

The left bar is the F11 HUD accent (`hzcAccent`). Tone does not change the bar. Green is `#5EE3A1`, amber `#F2A93B`, red `#FF5B5B`. A neutral chip uses the accent. Title, subtitle, and chip text are at least 13 px. Both HUD message movies carry the block. The reaction pill is unchanged.

Busy is option A. The title is the crosshair name from `HUDRolloverActivationData.sHeaderText` (`hzCrossName` on HUDMenu), read on the task thread only for a busy line with an empty name. A name that contains `<` is dropped. If the name is empty, the title is BUSY. Whether the rollover is still up when the busy line fires is **NOT FOUND**.

All of these cards, including the reaction pill, stay behind the existing `[Comms] ReactionCard` toggle (default 1). There is no new ini key.

Medical body group comes from `PersonalAlertsData` (`sAlertText`, a camel-split `sEffectIcon`, `sAlertSubText`). If that row is not present, the subtitle is the English change only ("Gained", "Cured", and so on).

Card size is `TextScale * HudScale`, and 1.25 more on the large HUD, clamped from 0.75 to 2.2. It does not multiply by `ScreenHeight / 1080`. The stage already scales with the screen.

`hzcCardPush` does not swallow a second identical line inside 3 seconds. The old backup path (`hzcRxOffer`) still pairs. Angry is amber `#F2A93B`. Calmed uses the accent. Calm stays green. Furious and caught stay red.

A card is taller than the gap between game lines (about 51). After placement, cards are stacked top to bottom with an 8 unit gap. The top card stays. x stays on the line's right edge.

The queue holds 8. An empty line is dropped. An exact duplicate already queued, including two lines that truncate to the same 200 bytes, is not stored again. The oldest note is dropped when the cap is full. Notes older than 3 seconds are dropped on the task thread. Setting lookups and form lookups are not in the sink.
