## Timing boundaries (design)

| Clock | Where | Precision | What it may measure |
| --- | --- | --- | --- |
| `QueryPerformanceCounter` | DLL, hooked `ASMovieRootBase::AdvanceFrame(bool)` | High-resolution (freq logged on dump) | **Root maintenance only** (`scope=asRootMaint`), split `rootT`/`rootF` by `a_next`. Not Movie::Advance, not timeline, not ENTER_FRAME. Public Scaleform 4.2 runs ENTER_FRAME before this callee; Starfield binary is not verified. Cheap orig vs AS ticks do not imply a broken QPC. |
| `GetTickCount64` | Existing plugin heartbeats / dump arming | ~15.6 ms | Ready/intro/settle/wait latch. **Not** a perf bucket. |
| `getTimer` | HUD perf helpers only (`hzPerfNow`) | **1 ms** | tick/content Date-allocation removed. Still millisecond wall time. Injected `hz41NowFn` remains the test clock. |
| `hz41Now()` (`Date.getTime`) | Splash, planet-alert, caret, other gameplay | **1 ms** | Unchanged. Do not use this for perf helpers. |

Native dump fields: per bucket `n` (calls), `avgUs`, `maxUs`, `cps` over the dump window. ActionScript dump fields: frames, content rebuilds, activation/item event counts vs actual payload changes, text-measure hits/misses, hold/bar paints. Source counts are **not** runtime measurements.

Production: `[Debug] PerfDiag=0` (default). No extra Invoke, no log, no file IO, no worker. One atomic/boolean check on the HUD advance when off.

Export: `[Debug] PerfDump` **0→1** arms one dump. Window starts at `max(HUD-ready 3s, intro resolved) + PerfSettleMs` (default 2000, clamp 0–10000). Intro resolved = done / skipped / timeout / exhausted / never armed. If the intro never armed (New Game), the window is HUD-ready + settle (fixed; it does not chase `now`). A pending intro that is still pending 15 s after HUD-ready falls back to HUD-ready. Capture length is `PerfDumpWait` (default 12). PauseMenu does not drop the request and does not dump; the first HudSafe frame after pause does not arm or dump. Resume needs no new 3 s wait once readyMs is latched. A later save-load, HUD root recreate, or adopt from a null HUD store un-arms (does not drop the request). The log line is two bounded parts: native `kDumpMax` 1400 and AS `kDumpAsMax` 1400 (~2.8k combined), truncated honestly. `movieAdvance` remains the combined compatibility total; `rootT`/`rootF` are the `a_next` split with histograms. AS clock token is `getTimer_ms`. No FunctionHandler / CreateFunction / QPC markers.

Prior ActiveBuffs work hit sync spdlog flush and unsafe worker teardown. This design does not add `std::thread`, `detach`, or a joinable logger. Repo pattern used: AdvanceFrame-thread Invoke + existing `REX::INFO`.

## Architecture evidence (read at `b924a4c`)

### Native

- `AddPermanentTask(Poll)` runs on **BSJobs** workers, not a dedicated UI thread (`src/main.cpp` comments at the task note, `Poll` ~4581). Scaleform Invoke is limited to each movie's own `AdvanceFrame`.
- `HookedAdvanceFrame` patches **`ASMovieRootBase::AdvanceFrame(bool)`** (vtable slot 2). That is root-maintenance, not `Movie::Advance` / timeline / ENTER_FRAME. Then `PollScaleform` (HUDMenu) or `PollMessages` (HUDMessagesMenu).
- Hover identity is **not** read in the DLL since v0.39 (`src/main.cpp` 34–36).
- `PublishCrossName` Invokes `hzCrossName` at 250 ms for Comms, not for the hover card.
- `ScanPushHud` / `ScanPushMsg` Invoke every 100 ms while the hand scanner is open.

### HUD hover (ActionScript `horizon_block.as`)

- `ENTER_FRAME` → `hzOnFrame` → `hzTgTick` → `hzT19Tick` every frame while the HUD runs.
- Data: `HUDRolloverActivationData`, `HUDRolloverItemData`, `HUDRolloverData`, `HudEnemyData`. No form ID / handle on the general interactable path. Scanner pick uses `uFormID|uHandle|...`.
- Cards are **reused** (`hzBuildTg19`). `hzT19Content` does `graphics.clear()`, text, keycaps, panel.
- Rebuild gate is string `hzT19Sig`. **EVIDENCE at `b924a4c`:** `hzOnTgAct` / `hzOnTgItems` always did `hzT19Ver++`, and ghost HP / hold fill sat in `hzT19Sig`, so provider pushes and animated fills forced `hzT19Content`. That is source rebuild cost, **not** a verified frametime cause.
- **HOLD5 at `b35bbf86` (independent `bc-b64f0feb`):** fingerprints omitted list `bStolen`/`bContraband`, button `bPressAndHold`/`bPressAndRelease`, and act `bShouldCompareItems`. In-place provider mutation skipped a required rebuild. That pin is **HOLD, not build-eligible**.
- This candidate uses length-prefixed tokens covering every field `hzT19Content` / `hzT19Buttons` / list rows draw, including activation `uWeightPrecision` and resolved font names. List-row KG in production is `toFixed(1)` (not per-row precision), so `ItemsPay` does not fingerprint unused list `uWeightPrecision`. Independent review of this new SHA is **not done**. Do not self-claim PASS.
- **EVIDENCE:** `FadeCards` (`hzFadeCards`) only snaps `hzFades` for fixed HUD cards (`hzShow` / `hzTickFades`). It does not gate `hzT19Tick`. That matches the report that fade on/off does not fix hover stutter. It does not prove animations are the cause.
- Vanilla prompt hide is re-applied every frame because timelines reset alpha (`hzT19HideA`). Skipping that without a new proof would regress prompts.

### Scanner (`actionscript/scanner/hzs_block.as`)

- `hzsTick` every frame: alpha-hide vanilla, optional `hzsDrawAll` when `hzsDirty` **or every 6 frames**. Per-panel `hzsSig` can skip a redraw after that walk. Freq / bioscan progress is why the 6-frame walk exists; removing it without another dirty path would hide live scan %. Not changed.

## Mandatory GFX splice gate (private HUD rebuild)

Do not ship a HUD `.gfx` for `PerfDiag=1` until every step below is done. `xmake` does not produce the movies.

1. Splice `actionscript/horizon_block.as` into both host `HUDMenu` classes (`hudmenu` and `hudmenu_lrg`).
2. In the **host** HUDMenu class (not the injected block), add:

   `import flash.utils.getTimer;`

   An import is not legal inside the injected block. Unqualified `getTimer()` in `hzPerfNow` needs this host import. Do not write a qualified utils-package call in the injected block: FFDec compiles that to a runtime name lookup of global `flash` and throws ReferenceError #1065.
3. After FFDec `-importScript`, export P-code for HUDMenu and **gate the package**:
   - The class import table includes `flash.utils.getTimer`.
   - `hzPerfNow` resolves `getTimer` as that imported function (not a global name lookup of `flash`, and not an unresolved `getTimer`).
   If either check fails, do not package the gfx.

`hzPerfNow` still try/catches `getTimer` and falls back to `Date.getTime`, and `hzOnFrame` wraps `hzPerfBegin`/`hzPerfEnd`, so a missed import cannot throw out of the frame tick. That fallback is a safety net, not a substitute for this import gate.

### Option B diagnostic build: second host import

The Option B memory sample (`hzMemTick`) reads unqualified `System.totalMemory`. In the same **host** HUDMenu class, next to the getTimer import, also add:

   `import flash.system.System;`

Gate it the same way: after `-importScript`, the exported P-code import table includes `flash.system.System`, and `hzMemTick` resolves `System` through that import (not a global name lookup of `flash`). `System.totalMemory` is **unverified in Scaleform 4 AS3**. If it throws or reads 0 in game, `hzMemTick` sets `memUnsupported=1` for the session and the native process private-bytes sample (`pmem*` fields, `type=P` ring events) stands in. A missed import is therefore not a crash, but it is still a failed gate for this build.

Option B output, all behind `PerfDiag=1` and printed at the one `PerfDump`:
- `perf dump ... as ...` gains `loop/exit/cmp/freq/jet/xh/act` `N`, `SumMs`, `Max` and `memUnsupported memN memMinKB memMaxKB memDrops memDropKB ringW`.
- `perf ring sum ...` gives native spike and process-memory counts and the AS ring header (`asN asLost memUnsupported offMs`).
- `perf ring t=<ms since window start> src=<N|AS> type=<R|P|T|C|M|Q> v=...` gives one line per event in time order. `R` is a rootT sample of 5 ms or more (us). `P` is a process private-bytes drop over 256 KB (KB). `T` is a target change, `C` a compass push run (max callback ms, `n`, `span`), `M` an AS memory drop over 256 KB (KB), and `Q` a hzQSync run. The AS times are moved onto the QPC clock with `offMs` (about 1 ms error).
